# لوحة عمليات التميم — المرحلة 1: وثيقة التصميم

- **التاريخ:** 2026-09-19
- **المستودع:** `csv-merger` ← يُعاد تسميته إلى `tamim-ops`
- **الحالة:** معتمد في جلسة التصميم، بانتظار مراجعة الوثيقة

---

## 1. الهدف

تحويل أداة الويب الحالية (دمج CSV وتقسيم الكروت) إلى **لوحة عمليات واحدة** تعمل داخل المتصفح بدون إنترنت، وتحلّ تدريجيًا محل قرابة 90 سكربت بايثون مكرّرة ومتفرّقة، بحيث:

- لا تتكرّر أي منطقية: كل عملية تُكتب مرة واحدة، والفروق بين الشركات تصبح **بيانات إعداد** لا **كود**.
- كل ما يُنتَج دقيق: القيم نصوص دائمًا، وأي خلل في المدخلات يُكشف قبل التنزيل.
- تبقى الأداة بلا مكتبات خارجية، بلا خطوة بناء، وتعمل من الرابط أو من مجلد على الجهاز.

### المراحل (لكل مرحلة وثيقة تصميم وخطة وتنفيذ مستقل)

| المرحلة | المحتوى |
|---|---|
| **1 (هذه الوثيقة)** | تُنفَّذ في ثلاث دفعات، لكل دفعة خطة مستقلة، وكل دفعة تُنشر وتعمل وحدها: |
| **1أ — الأساس** | نقل `app.js` إلى وحدات، إطار اللوحة (الشريط الجانبي والتنقّل)، العمل بدون نت، نقل الدمج والتقسيم الحاليين **بنفس سلوكهما** — بلا أي ميزة جديدة؛ ثم إعادة التسمية والنشر |
| **1ب — الاستيراد** | الكرت الموحد، ملفات إعدادات الشركات (المخطط والقواعد والتعرّف)، قارئ `batchTxt`، الفحوص، أداة الاستيراد، IndexedDB، حزمة الإعدادات، سلة العمل، محرّر ملفات الإعداد |
| **1ج — الإكمال** | فتح ملفات Excel المشفّرة، معالج شركة جديدة، الإعدادات الأولية (حوالي 25 شركة)، اختبارات المطابقة مع بايثون |
| 2 | التقسيم المتقدم والتصدير (أخذ نطاق أسطر مع أكواد تمبلت، سحب كمية وإبقاء الباقي، قوالب Batch، إضافة نص لنهاية الأسطر، تبديل أعمدة) |
| 3 | أدوات السيريال (توليد أكواد، توليد سيريال، استخراج عمود، فلتر طول، مطابقة، بحث في مجلد) |
| 4 | ترجيع الكروت |
| 5 | الفواتير والتقارير |

### 3.2 قواعد الوحدات

- كل ملف في `js/core` يعرّف دوالّه داخل دالة فورية ويسجّلها في `globalThis.Tamim.core.<name>`، ويصدّرها بـ `module.exports` عند وجود `module`. الاعتماد بين الوحدات يمرّ عبر `Tamim.core` في المتصفح و`require` في Node.
- لا ES Modules (المتصفح يمنعها عند الفتح من `file://`).
- `index.html` يحمّل الملفات بترتيب ثابت: `core` (حسب الاعتماد) ثم `app` ثم `tools` ثم `shell` أخيرًا.
- لا ملف في `js/core` يلمس `document` أو `window` أو `indexedDB`.
- الحدّ المرشد لحجم الملف: 600 سطر؛ ما يتجاوزه يُقسَّم حسب المسؤولية.

### 3.3 الواجهة

- RTL عربي، بنفس لغة التصميم الحالية (بطاقات، شارات، ألوان الملفات).
- الشريط الجانبي في المرحلة 1: **الرئيسية · استيراد كروت المورد · الدمج والتقسيم · الإعدادات**. أدوات المراحل اللاحقة لا تظهر حتى تُبنى.
- التنقّل بالمسارات `#/home`، `#/import`، `#/merge`، `#/settings`.
- على الشاشات الضيقة يتحوّل الشريط الجانبي إلى قائمة علوية.

## 4. نموذج الكرت الموحد

```
Card = { pin: string, serial: string, company: string, category: string }
```

- `company` و `category` هنا **أكواد النظام** (ما يُكتب في العمودين 3 و4)، لا الأسماء.
- لا تُحوَّل أي قيمة إلى رقم في أي مرحلة.
- **التطبيع الإلزامي** (يُطبَّق على كل خلية قبل أي قاعدة):
  1. حذف المسافات في الطرفين.
  2. تحويل الأرقام العربية والفارسية إلى لاتينية.
  3. إذا كانت القيمة تطابق `^-?\d+\.0+$` تُحذف الكسور (`12345.0` ← `12345`).

## 5. ملفات إعدادات الشركات (Profiles)

### 5.1 المخطط

```json
{
  "id": "معرّف فريد",
  "name": "الاسم المعروض",
  "updatedAt": "2026-09-19T10:00:00.000Z",
  "updatedBy": "اسم الجهاز",

  "input": {
    "format": "table",
    "sheets": "all",
    "skipSheets": ["ملخص", "summary"],
    "header": "auto",
    "delimiter": "auto"
  },

  "company":  { "from": "fixed", "value": "abc" },
  "fields": {
    "pin":      { "names": ["PIN", "الرقم السري"], "index": 2 },
    "serial":   { "names": ["SN", "السيريال"],      "index": 1 },
    "category": { "from": "column", "names": ["Value", "الفئة"], "index": 5 }
  },

  "rules": [
    { "op": "digitsOnly", "field": "category" }
  ],

  "categoryCodes": { "10": "10", "20": "20" },

  "output": {
    "columns": ["pin", "serial", "company", "category"],
    "fileName": "{company}_{category}.csv",
    "groupBy": "category",
    "chunkSize": 0,
    "delimiter": ",",
    "bom": false,
    "header": false,
    "lineEnding": "\r\n"
  },

  "detect": { "headers": ["PIN", "SN", "Value"], "fileName": [], "sheetNames": [] },
  "expect": { "digitsOnly": true }
}
```

### 5.2 مصادر القيم

**`input.format`**: `table` (Excel أو CSV) أو `batchTxt` (انظر 6.4).

**`input.sheets`**: `all` أو `first`. الأوراق التي يحتوي اسمها على أي كلمة من `skipSheets` تُتجاهل.

**`input.header`**: `yes` أو `no` أو `auto` (نفس منطق الاكتشاف الحالي `detectHasHeader`).

**تطبيع العناوين والكلمات** (للمطابقة فقط، لا يغيّر البيانات): التطبيع الإلزامي (قسم 4) + تحويل الأحرف إلى صغيرة + دمج المسافات المتتالية في مسافة واحدة.

**تحديد عمود (`pin`، `serial`، `category` من نوع column، و`company` من نوع column):**
1. إن وُجد صف عناوين: يُبحث عن أول اسم في `names` يطابق عنوان عمود مطابقة تامة بعد التطبيع، ثم مطابقة جزئية (العنوان يحتوي الاسم).
2. إن لم يُعثر على اسم أو لا يوجد صف عناوين: يُستخدم `index` (يبدأ من 0).
3. إن لم يتوفّر أيّهما: **خطأ في ملف الإعداد** يُعرض قبل المعالجة.

**`company.from`**:
- `fixed` + `value`.
- `ask`: يُطلب الكود عند الاستيراد، ويُقترح آخر كود استُخدم مع هذا الملف.
- `column` + `names`/`index` + `map` اختياري.
- `sheetName` + `map` (مفتاح ← كود) + `fuzzy: true|false`. الكلمة الأولى من اسم الورقة تُطابَق مع مفاتيح `map` بعد التطبيع؛ ومع `fuzzy` تُقبل أقرب تهجئة (مسافة تحرير ≤ 2 لكلمة طولها ≥ 5)، مع تحذير يذكر التصحيح.

**`fields.category.from`**:
- `column` + `names`/`index`.
- `fileName` + `pick: "firstNumber" | "lastNumber"` — أول/آخر عدد متصل في اسم الملف دون الامتداد.
- `sheetName` + `pick` بنفس المعنى.
- `batchHeader` + `key` (مثل `FaceValue`).
- `fixed` + `value`.
- `ask`: يُطلب عند الاستيراد لكل ملف.

### 5.3 القواعد (`rules`)

تُطبَّق بالترتيب على كل صف بعد التطبيع. `field` واحد من `pin`، `serial`، `category`.

**الصف الفارغ** يُحدَّد **قبل** تطبيق القواعد: إذا كانت القيم الخام لكل الحقول المقروءة من أعمدة (السري، السيريال، والفئة إن كان مصدرها عمودًا) فارغة، يُتجاهل الصف ويُحسب ضمن "الصفوف الفارغة المتجاهلة". وإلا يدخل المعالجة ويخضع للفحوص.

| العملية | المعاملات | المعنى |
|---|---|---|
| `fillDown` | `field` | خلية فارغة تأخذ آخر قيمة غير فارغة فوقها في نفس الورقة |
| `digitsOnly` | `field` | إبقاء الأرقام فقط |
| `padStart` | `field`, `length`, `char` (افتراضي `"0"`) | إكمال من اليسار حتى الطول |
| `concat` | `target`, `parts: [{field, padStart?}]`, `separator` (افتراضي `""`) | بناء قيمة من عدة حقول (تُقرأ القيم الأصلية قبل الكتابة) |
| `copy` | `from`, `to` | نسخ قيمة حقل إلى آخر |
| `replace` | `field`, `find`, `with` | استبدال نصي حرفي لكل التكرارات |
| `map` | `field`, `table`, `strict` | تحويل عبر جدول؛ مع `strict: true` القيمة غير الموجودة خطأ |
| `prefixIf` | `field`, `value`, `fileNameContains: []` | إضافة بادئة إذا احتوى اسم الملف أيًّا من الكلمات |

أي عملية أو معامل غير معروف ← الملف يُرفض عند الحفظ والاستيراد مع رسالة تحدّد الموضع.

### 5.4 أكواد الفئات

- بعد القواعد، قيمة `category` هي **الفئة الخام**.
- الكود النهائي = `categoryCodes[الفئة الخام]`.
- الفئات التي ليس لها كود تظهر في **نافذة تأكيد أكواد الفئات**، مقترحًا لكل منها "الأرقام فقط من الفئة الخام"، مع زر "موافقة على الكل". ما يُؤكَّد يُحفظ في `categoryCodes`.
- لا تبدأ المعالجة وأي فئة بلا كود.

### 5.5 الإخراج

- `columns`: ترتيب أي تبديل للحقول الأربعة (مثال ليبيانا: `["serial","pin","company","category"]`).
- الملفات تُفصل دائمًا حسب كود الشركة. `groupBy`: `category` (ملف لكل شركة وكود فئة) أو `none` (ملف واحد لكل شركة).
- `chunkSize`: `0` بلا تقسيم؛ وإلا يُقسَّم كل ملف إلى أجزاء بهذا الحجم.
- التنزيل: ملف ناتج واحد ← يُنزَّل CSV مباشرة. أكثر من ملف ← ZIP فيه مجلد لكل كود شركة.
- `fileName` يقبل المتغيرات: `{company}` `{category}` (الكود) `{categoryRaw}` `{part}` (رقم الجزء، يبدأ من 1) `{source}` (اسم الملف المصدر بلا امتداد) `{sourceNumber}` (أول عدد في اسم الملف المصدر) `{date}` (`YYYY-MM-DD`).
- إذا أنتج نمط الاسم اسمين متطابقين لملفين مختلفين ← يُضاف `_2`، `_3`… مع تحذير.
- الاقتباس: كما في Python `csv.writer` الافتراضي — القيمة تُحاط بعلامتي تنصيص فقط إذا احتوت الفاصل أو تنصيصًا أو سطرًا جديدًا.
- الإعداد الافتراضي لملف إعداد جديد: `,` / بلا BOM / بلا عناوين / `\r\n`.

### 5.6 التعرّف التلقائي

لكل ملف تُحسب درجة لكل ملف إعداد (0–100) من ثلاثة معايير، **يُحتسب منها فقط ما عرّفه ملف الإعداد** (قائمة غير فارغة):

| المعيار | الوزن | قيمة المعيار (0–1) |
|---|---|---|
| `detect.headers` | 60 | نسبة الكلمات الموجودة ضمن عناوين الملف بعد التطبيع (ملف بلا عناوين ← 0) |
| `detect.fileName` | 25 | 1 إذا احتوى اسم الملف أي كلمة منها |
| `detect.sheetNames` | 15 | 1 إذا احتوى اسم أي ورقة أي كلمة منها (CSV/TXT ← 0) |

الدرجة = 100 × (مجموع الوزن × القيمة) ÷ (مجموع أوزان المعايير المعرَّفة). ملف إعداد بلا أي معيار درجته 0 دائمًا (يُختار يدويًا فقط).

القرار: ≥ 70 ← اختيار تلقائي. 40–69 ← اقتراح يتطلب تأكيدًا. < 40، أو تعادل أعلى درجتين ← يختار المستخدم أو يفتح المعالج.

### 5.7 معالج شركة جديدة

1. يقرأ الملف ويعرض أول 20 صفًا.
2. يخمّن الأعمدة بقوائم كلمات (سري/PIN/password/كود…، سيريال/SN/serial/card…، فئة/value/price/denomination…) كما في Any EX.
3. يطلب: الاسم، كود الشركة، مصدر الفئة، والقواعد (اختيارية).
4. يعرض معاينة الناتج لأول 10 كروت.
5. يحفظ ملف إعداد جديد، مع `detect.headers` = عناوين الملف.

ويتوفّر في الإعدادات محرّر نموذجي لكل حقل + عرض JSON للمتقدمين، مع تحقّق قبل الحفظ.

### 5.8 الإعدادات الأولية

كل محوّل بايثون **في آخر إصدار له** يُحوَّل إلى ملف إعداد، وتُجمع في **حزمة إعدادات أولية** تُحفظ في `Desktop\tamim-private\` — **خارج المستودع العام** — وتُستورد مرة على كل جهاز.

## 6. قراءة الملفات

### 6.1 CSV/TXT
المنطق الحالي كما هو: اكتشاف الترميز (UTF-8 / UTF-16 / Windows-1256) والفاصل.

### 6.2 Excel `.xlsx` / `.xlsm`
القارئ الحالي كما هو، مع إضافة: كل خلية رقمية (`t` = `n` أو غائب، وغير مصنّفة تاريخًا) قيمتها الخام تحتوي `E`/`e`، أو فيها أكثر من 15 رقمًا (بعد حذف الإشارة والفاصلة العشرية والأصفار في البداية)، تُسجَّل في قائمة **خلايا مفقودة الدقة** (الورقة، الصف، العمود) تُرجع مع البيانات. السبب: Excel لا يحفظ أكثر من 15 رقمًا في الخلية الرقمية، فالرقم الـ16 وما بعده يكون قد تغيّر فعلًا.

### 6.3 الملفات المحمية بكلمة سر
- ملف يبدأ بتوقيع OLE2 (`D0 CF 11 E0`) يُفتح بـ `ole.js`:
  - إن احتوى تيّاري `EncryptionInfo` و`EncryptedPackage` ← ملف Excel مشفّر.
  - غير ذلك ← ملف `.xls` قديم ← رسالة: "افتحه في Excel واحفظه بصيغة .xlsx".
- **Agile Encryption** (Excel 2010 فما بعد) مدعوم: اشتقاق المفتاح (SHA-512، عدد التكرارات من `spinCount`) وفك AES-CBC على أجزاء 4096 بايت، ثم يمر الناتج إلى قارئ xlsx العادي.
  - تم التحقق من ملفات مورد حقيقية مشفّرة: Agile، SHA-512، `spinCount` = 100000، AES-256.
  - الـ 100000 دورة SHA-512 تُنفَّذ بتنفيذ **متزامن** لـ SHA-512 داخل `crypto.js` (استدعاء `crypto.subtle.digest` غير المتزامن 100000 مرة بطيء جدًا)، ويُتحقق منه باختبارات متجهات SHA-512 القياسية. فك AES-CBC عبر `crypto.subtle`.
  - تم التحقق أن `crypto.subtle` و IndexedDB متاحان عند الفتح من `file://` في Edge وChrome.
  - الملف التجريبي المشفّر يُنشأ بـ `msoffcrypto-tool` (يدعم التشفير Agile) بكلمة سر معروفة.
- التحقق من كلمة السر عبر `encryptedVerifierHashInput/Value`؛ كلمة سر خاطئة ← رسالة واضحة وإعادة طلب.
- **Standard Encryption** (Excel 2007) غير مدعوم ← رسالة: "افتح الملف في Excel حديث واحفظه من جديد".
- كلمة السر لا تُحفظ في أي مكان، ولا تُطبع في أي سجل.

### 6.4 ملفات Batch النصية (`batchTxt`)
- أسطر الرأس بصيغة `مفتاح:قيمة` حتى سطر `[BEGIN]`.
- أسطر البيانات بين `[BEGIN]` و`[END]`، كل سطر يُقسَّم على المسافات، و`fields.pin.index` و`fields.serial.index` يحددان الموضعين.
- غياب `[BEGIN]` أو `[END]` ← خطأ.
- سطر عدد أجزائه لا يساوي عدد أجزاء أغلب الأسطر ← خطأ يذكر رقم السطر (لا يُتجاهل بصمت).

## 7. الفحوص

كل فحص يُرجع `{ level: "error"|"warning"|"info", code, message, file, sheet, rows: [] }`. تُعرض أول 20 صفًا لكل فحص مع العدد الكلي.

**أخطاء (تمنع التنزيل والإرسال لسلة العمل):**

| الكود | الشرط |
|---|---|
| `EMPTY_FIELD` | صف غير فارغ (بتعريف 5.3) لكن السري أو السيريال فارغ بعد القواعد |
| `PRECISION_LOST` | السري أو السيريال جاء من خلية "مفقودة الدقة" (6.2)، أو نصه بصيغة علمية `^\d(\.\d+)?[eE]\+?\d+$` |
| `DUP_PIN` / `DUP_SERIAL` | تكرار داخل ملف أو بين ملفات نفس الدفعة (إلا إذا كان الحقلان مصدرهما واحدًا عبر `copy`، فيُفحص أحدهما فقط) |
| `NO_CATEGORY_CODE` / `NO_COMPANY_CODE` | فئة أو شركة بلا كود بعد نافذة التأكيد |
| `BATCH_QUANTITY` | في `batchTxt`: قيمة `Quantity` في الرأس ≠ عدد الأسطر |
| `BATCH_FORMAT` | في `batchTxt`: غياب `[BEGIN]`/`[END]` أو سطر مشوّه |
| `PROFILE_INVALID` | ملف الإعداد لا يجتاز التحقق أو عمود مطلوب غير موجود |
| `MAP_STRICT` | قيمة غير موجودة في جدول `map` صارم |

**تحذيرات (تتطلب ضغط "اطّلعت ومتابعة"):**

| الكود | الشرط |
|---|---|
| `LENGTH_OUTLIER` | طول سري/سيريال يخالف الطول الأكثر تكرارًا في نفس الملف |
| `NON_DIGIT` | حرف غير رقمي في حقل، وملف الإعداد يضع `expect.digitsOnly: true` |
| `SAME_FILE_TWICE` | نفس بصمة SHA-256 لملف استُورد في هذه الجلسة |
| `NAME_COLLISION` | نمط اسم الملف أنتج اسمين متطابقين (أُضيف `_2`…) |
| `FUZZY_COMPANY` | كود الشركة حُدد بأقرب تهجئة لاسم الورقة |
| `COLUMN_BY_INDEX` | الملف فيه صف عناوين، لكن عمودًا حُدد **بالرقم** لأن أيًّا من أسمائه لم يطابق (أهم مؤشر على أن المورد غيّر ترتيب الأعمدة) |
| `DATE_FORMATTED_ID` | خلية سري أو سيريال منسّقة في Excel كتاريخ/وقت فحُوّلت إلى نص تاريخ |

**معلومات:** عدد الكروت لكل (شركة، فئة)، الصفوف الفارغة كليًا المتجاهلة، وسطر المطابقة: **الصفوف المقروءة = الكروت المكتوبة + الصفوف الفارغة المتجاهلة**. أي اختلاف في هذه المعادلة خطأ داخلي يمنع التنزيل.

## 8. أداة استيراد كروت المورد

1. **إسقاط:** ملفات متعددة أو مجلد (`webkitdirectory`)؛ الصيغ: xlsx، xlsm، csv، txt.
2. **التعرّف:** بطاقة لكل ملف فيها ملف الإعداد المختار والدرجة وزر تغيير؛ ملف مشفّر يطلب كلمة سره؛ ملف بلا تطابق يعرض "إنشاء شركة جديدة" (المعالج).
3. **أسئلة الاستيراد:** كود الشركة لملفات `company.from = ask`، والفئة لملفات `category.from = ask`.
4. **نافذة أكواد الفئات:** للفئات التي بلا كود فقط.
5. **تقرير الفحص** (قسم 7).
6. **الملخص:** جدول (الشركة، الفئة، العدد، اسم الملف الناتج) + سطر المطابقة.
7. **الإجراءات:** "تنزيل" (ملف واحد ← CSV، أكثر ← ZIP بمجلد لكل شركة) و"إرسال إلى سلة العمل".

## 9. الحفظ والمشاركة

### 9.1 IndexedDB
- قاعدة بيانات `tamim`، الإصدار 1، مخزنان:
  - `profiles` (المفتاح `id`).
  - `meta` (مفتاح/قيمة): `deviceName`، `lastBackupAt`، `lastChangeAt`، `lastCompanyCode` لكل ملف إعداد.
- كل حفظ لعنصر يضبط `updatedAt` و`updatedBy`، ويحدّث `lastChangeAt`.
- عند أول تشغيل يُطلب اسم الجهاز، ويُستدعى `navigator.storage.persist()`.
- المراحل اللاحقة تضيف مخازن جديدة برفع رقم الإصدار، دون المساس بالموجود.

### 9.2 حزمة الإعدادات
```json
{
  "format": "tamim-settings",
  "formatVersion": 1,
  "exportedAt": "ISO",
  "device": "اسم الجهاز",
  "stores": { "profiles": [ ... ] }
}
```
- **التصدير:** كل المخازن أو ما يختاره المستخدم؛ اسم الملف `tamim-settings-<الجهاز>-<YYYY-MM-DD>.json`؛ يحدّث `lastBackupAt`.
- **الاستيراد:** يرفض أي ملف `format` أو `formatVersion` غير معروف، ويتحقق من كل عنصر. ثم يعرض لكل عنصر إحدى الحالات:
  - **جديد** ← الافتراضي: إضافة.
  - **مطابق** ← لا شيء.
  - **مختلف والوارد أحدث** ← الافتراضي: استبدال.
  - **مختلف والمحلي أحدث أو مساوٍ** ← الافتراضي: إبقاء المحلي.
  لكل عنصر مختلف: عرض الفروق حقلًا بحقل وإمكانية عكس الاختيار. لا يُطبَّق شيء قبل "تطبيق".
- الاستيراد **لا يحذف** أي عنصر محلي. الحذف على جهاز لا ينتقل للأجهزة الأخرى في هذه المرحلة.
- **تنبيه النسخ الاحتياطي** في الرئيسية إذا كان `lastChangeAt > lastBackupAt` ومرّ على `lastBackupAt` (أو على أول تشغيل) 7 أيام.

## 10. سلة العمل

- في الذاكرة فقط؛ **لا تُحفظ الكروت أبدًا** في أي تخزين.
- كل عنصر: `{ id, name, header: string[] | null, rows: string[][], origin: { tool, files, profileId? }, createdAt }`. الكروت الناتجة من الاستيراد تُحفظ بأعمدة `output.columns` وبلا عناوين.
- أداة الدمج والتقسيم تقبل عناصر السلة كمدخلات (تمرّ عبر `analyzeRows` الحالية دون تعديلها).
- عند محاولة إغلاق الصفحة والسلة غير فارغة ← تنبيه المتصفح القياسي (`beforeunload`).
- زر "تفريغ السلة" في الرئيسية.

## 11. العمل بدون نت

- `sw.js` يخزّن قائمة ثابتة بكل ملفات التطبيق باسم ذاكرة يحتوي رقم الإصدار (`tamim-v<N>`)، ويخدمها أولًا من الذاكرة.
- عند التفعيل يحذف الذواكر ذات الإصدارات الأخرى.
- عند وجود نسخة جديدة منتظرة يظهر شريط "يوجد تحديث — اضغط لإعادة التحميل"؛ لا إعادة تحميل تلقائية.
- رقم الإصدار موجود في مكان واحد (`js/app/version.js`) ويستخدمه `sw.js` وروابط الملفات في `index.html`.
- عند الفتح من `file://` لا يُسجَّل Service Worker والصفحة تعمل مباشرة؛ تخزينها مستقل، وحزمة الإعدادات هي الجسر.

## 13. الاختبارات

- `node tests/run.js` يشغّل كل ملفات `tests/*.test.js`، ويطبع النتيجة، ويخرج بكود ≠ 0 عند أي فشل.
- اختبارات وحدة لكل ملف في `js/core`، منها: كل قاعدة في 5.3، كل مصدر في 5.2، كل فحص في 7، التعرّف التلقائي، أسماء الملفات والتصادم، `batchTxt`، علامات فقد الدقة، OLE2، فك التشفير (ملف تجريبي مشفّر بكلمة سر معروفة)، ومقارنة حزمة الإعدادات.
- الملفات التجريبية بكروت **وهمية فقط**.
- **اختبارات المطابقة مع بايثون** في `Desktop\tamim-private\parity\`:
  - المدخلات: **ملفات الموردين الحقيقية** الموجودة على الجهاز (نسخ منها داخل `tamim-private` فقط)، لأنها تحمل خصوصيات حقيقية لا تظهر في بيانات وهمية (عناوين في صف غير الأول، خلايا فئة مدمجة، تنسيقات). وحين لا يوجد ملف حقيقي لشركة يُصنع ملف وهمي بنفس شكلها.
  - المخرجات المتوقعة: ما ينتجه سكربت البايثون الأصلي (آخر إصدار) على نفس المدخل، عبر سكربت تشغيل يستبدل حوارات tkinter. تم التحقق من توفّر openpyxl وpandas وmsoffcrypto على Python الجهاز.
  - المقارنة: نفس أسماء الملفات، ونفس الصفوف بنفس الترتيب ونفس القيم. نهايات الأسطر والسطر الأخير الفارغ لا تُقارن (سكربتات البايثون نفسها غير متّسقة فيها).
  - أي فرق مقصود يُسجَّل صراحة في ملف الاختبار مع سببه.
  - إن لم يوجد المجلد تُتخطّى هذه الاختبارات برسالة واضحة.
- **CI:** مهمة `test` تشغّل `node tests/run.js`، ومهمة النشر تعتمد عليها (`needs: test`).
- قبل كل دمج في `main`: فحص يدوي في المتصفح لكل أداة معدّلة (Chrome، سطح المكتب وعرض الجوال، ومن `file://`).

## 16. ملاحظات التنفيذ (أُضيفت أثناء التنفيذ)

- **البحث عن صف العناوين:** إن احتوى ملف الإعداد أسماء أعمدة للسري والسيريال، يُبحث في أول 25 صفًا عن أول صف فيه اسم لكل منهما (مطابقة تامة بعد التطبيع)، وتُتجاهل صفوف العنوان فوقه. وإلا يُستخدم أول صف غير فارغ (القسم 5.2).
- **العمود الفارغ:** إن طابقت عدة أعمدة أسماء الحقل وكان أولها فارغًا تمامًا، يُستخدم التالي (مثال: "الكود" فارغ والرقم في "الرقم السري (PIN)").
- **`COLUMN_BY_INDEX`** لا يظهر لملف إعداد بلا أسماء (رقم فقط) — فقط حين تُعطى أسماء ولا تطابق.
- **التعرّف عند تساوي الدرجة:** يُرجَّح ملف الإعداد الذي طابق عددًا أكبر من العناوين (الأكثر تحديدًا)؛ التعادل الحقيقي ← اختيار يدوي.
- **اقتراح كود الفئة:** قيمة جاهزة (أحرف لاتينية وأرقام فقط، مثل `10` أو `h10`) تُقترح كما هي؛ النص الوصفي تُقترح أرقامه.
- **إصلاح في قارئ Excel:** الخلايا والصفوف ذاتية الإغلاق (`<c …/>`, `<row …/>`) كانت تبتلع القيمة التالية فتنتقل القيم إلى أعمدة خاطئة. اكتُشف بمقارنة ملف مورد حقيقي مع openpyxl، ويؤثر على أداة الدمج المنشورة سابقًا.
- **اختبارات المطابقة (29 حالة، كلها ناجحة):** الفروق المقصودة الموثقة — `kafaa.py` كان يحذف الصفر من أول الرقم السري، و`smart_wave.py`/`edah.py` يحذفان الأصفار من أول السيريال (pandas)، و`star.py` يكتب الفئة `90.0`؛ اللوحة تحفظ القيم كما هي. أسماء بعض الملفات أوضح (`orang-net_` بدل `ox_`، `LIBYA-SOFT_h10`).
- **اكتُشف في بيانات حقيقية:** ملف giga فيه 80 كرتًا مكررًا (نفس القسيمة والرقم) كان السكربت القديم يُخرجها مرتين؛ اللوحة تمنع التنزيل.
